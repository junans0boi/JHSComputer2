# ADR-014: 공개 벤치마크·추천 콘텐츠 표시 경계

## 상태

수락됨 — 2026-09-09

## 문맥

벤치마크와 추천 견적은 외부 수집 데이터와 실제 판매 단위에서 시작한다. 내부 데이터에는 원천 조합 키, 수집 출처, 원본 상품명과 근거 수준이 필요하지만, 이를 고객 화면에 그대로 노출하면 `9800x3d-rx9070xt` 같은 내부 식별자와 수집처 문체가 사용자 경험을 해친다. 또한 수집 조합 수와 FPS 근거 보유 조합 수를 하나의 목록으로 처리하면, 수집된 조합이 하나뿐인 것처럼 오해하게 된다.

## 결정

1. 내부 식별자(`COMBO_KEY`)와 공개 표시명(`PublicComboName`)을 분리한다. 공개 표시명은 JHS 정규화 규칙으로 CPU/GPU 모델을 사람이 읽을 수 있게 만든다.
2. 벤치마크 화면은 `수집 조합`과 `FPS 근거 보유 조합`을 구분한다. FPS가 없는 조합은 수치를 발명하지 않고 `성능 데이터 준비 중` 상태로 표시한다.
3. 고객용 추천 제목·요약·설명은 JHS 콘텐츠 템플릿으로 작성한다. 내부에는 `SOURCE_TYPE`, 원본 식별자, 근거 메타데이터를 계속 보존한다.
4. 외부 보고값이나 수집 데이터는 JHS 자체 측정으로 표현하지 않는다. `MEASURED`, `SOURCE_REPORTED`, `DERIVED`, `NONE` 근거 분류를 유지한다.
5. 추천 공개 목록은 실제 활성 판매 단위와 중복 없는 목적·가격대·CPU/GPU 조합을 기준으로 확장한다. 단순히 게시물 수를 복제하지 않는다.
6. 서로 다른 원천 키가 같은 공개 CPU/GPU 모델로 정규화되면 공개 목록에서는 하나로 합치고, 상세 조회는 원천 키 전체를 대상으로 한다. 동일한 출처 보고 FPS가 해상도별로 반복되면 독립 측정으로 표시하지 않고 원본 보고값 한 건만 노출한다.
7. 견적왕 게임 표의 `평균프레임`은 게임당 단일 보고값이고 `FHD/QHD/UHD` 열은 지원 옵션 문구이므로 해상도별 FPS 행으로 복제하지 않는다. 해상도별 게임 차트가 있는 외부 벤치마크는 테스트 시스템·원문 URL을 보존한 `SOURCE_REPORTED` 원본으로만 수집하며, 없는 해상도는 비워 둔다.

## 결과

- 고객은 수집 규모와 실제 FPS 근거 규모를 혼동하지 않는다.
- URL/API 조회에는 내부 키 호환성이 유지되고, 화면에는 일관된 JHS 표시명이 나온다.
- 콘텐츠 문체는 서비스가 통제하지만, 근거와 출처를 허위로 바꾸지 않는다.

## 기각한 선택

- FPS가 없는 조합에 임의의 FPS를 생성: 신뢰도 훼손
- 원천 출처 필드를 삭제: 재현·검수·운영 추적 불가
- 내부 조합 키를 그대로 고객 화면에 표시: 사용자 이해도와 검색성이 낮음
- 단일 평균 FPS를 FHD/QHD/UHD에 복제: 해상도별 성능 차이를 숨기고 원본 행 수를 부풀림
