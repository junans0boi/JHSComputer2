# FPS 선택기와 원본 수집 확장 경계

작성일: 2026-09-10  
관련 Wayfinder: #63  
관련 스펙: `docs/specs/2026-09-fps-selector-and-source-expansion.md`

## 결정

벤치마크 화면의 선택기는 추천 조합이 아니라 `GameFpsObservation`이 하나 이상 있는
공개 CPU/GPU 조합을 기준으로 만든다. 사용자가 CPU와 GPU를 별도로 선택하면 서버는
정규화된 두 모델의 정확한 조합을 찾고, 그 조합의 해상도·옵션별 관측값만 표에 넣는다.

견적왕·왕가PC 데이터는 다음 두 경계를 유지한다.

- 원문에 숫자 FPS, 해상도, 품질 옵션, CPU, GPU가 함께 있으면 `SOURCE_REPORTED` FPS
  관측값으로 적재한다. 현재 견적왕 표처럼 평균 FPS와 해상도 지원 문구만 있는 경우는
  이 조건을 만족하지 않는다.
- 추천 조합, 조립 PC 부품, 가격, “이 해상도까지 지원” 문구만 있으면 추천/견적 출처로
  보존하고 FPS 관측값으로 승격하지 않는다.

ComputerBase는 기사별 테스트 시스템을 `benchmark_builds.RAW_JSON`에 보존한다. 현재
두 게임 테스트 기사는 9800X3D를 명시하지만, 이후 다른 CPU 기사도 기사 원문에서
확인한 CPU를 사용한다. 수집기는 고정 CPU 상수를 기사 전체에 적용하지 않는다.

FPS 원본과 집계 결과의 유일키에는 `OPTION_KEY`와 `SOURCE_CONDITION_KEY`를 포함한다.
같은 조합·게임·해상도라도 네이티브/업스케일링/레이 트레이싱 등 옵션이나 원본 기사·
테스트 조건이 다르면 서로 다른 관측 행으로 보존한다.

## 이유

기존 화면은 수집 조합 전체를 목록으로 보여줘 FPS 근거 조합과 추천 조합을 혼동하게
했고, 현재 ComputerBase 수집기는 9800X3D와 GPU 10개를 조합해 `FPS 조합 10개`라는
지표를 만들었다. 선택기와 표를 FPS 근거 집합에 한정하면 사용자가 보는 선택지와
실제 표시 가능한 숫자가 일치한다.

견적왕 원본의 해상도 열은 지원 옵션 설명이며 해상도별 FPS 측정값이 아니다. 이를
세 해상도에 복제하면 FHD/QHD/4K 성능이 같아지는 잘못된 화면이 생긴다.

## 결과

- `/api/benchmarks/selector-options`는 FPS 근거 조합에서 CPU/GPU 선택지와 정확한 조합
  참조를 반환한다.
- `/benchmarks?cpu=...&gpu=...`는 선택 조합의 게임 표와 CPU/GPU 벤치마크를 조회한다.
- `Cinebench 2024 · 싱글코어`, `Cinebench 2024 · 멀티코어`는 동일 테스트·버전·지표
  그룹만 각각 비교한다.
- 수집기 dry-run은 원본 행·기사·CPU/GPU·게임·해상도·옵션을 보고하고, `--apply` 때만
  DB를 변경한다.
- 근거가 없는 해상도 셀은 빈 값으로 남으며, 현재 값이나 다른 해상도 값을 복사하지
  않는다.

## 화면 경계

`/benchmarks`는 선택한 CPU·GPU 조합의 게임 FPS와 부품 벤치마크를 비교하는 화면으로
한정한다. 추천 견적 조합과 추천 사유는 `/recommendations`에서 제공하며, 벤치마크
표 안에 추천 조합 목록을 반복해서 렌더링하지 않는다. 출처 URL·테스트 시스템·수집
회수 같은 provenance는 API의 근거 필드로 보존하되, FPS 셀에는 FPS와 체감 등급만
표시해 결과 비교를 우선한다.
