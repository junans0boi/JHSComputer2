# 복수 workload 기반 서버 견적 미리보기

자동 견적은 브라우저의 고정 템플릿이 직접 부품을 결정하는 구조에서, `WorkloadProfile`, `BudgetProfile`, `PreferenceProfile`, `StorageDemand`를 입력받아 서버가 실제 판매 단위와 호환성·가격·재고를 검증한 뒤 `QuoteCandidate`를 반환하는 구조로 전환한다. 서버의 `POST /api/quotes/preview`를 견적 후보 생성의 외부 seam으로 삼아 프론트·주문 전환·테스트가 같은 규칙을 사용하게 하며, 기존 v1 입력은 adapter로 읽기 호환한다.

## 고려한 선택지

- 브라우저에서 계속 후보를 생성: 데이터·규칙이 클라이언트에 복제되고 주문 전 검증과 불일치할 수 있어 채택하지 않는다.
- AI가 부품을 직접 선택: 재현성·호환성·가격 검증이 약해져 채택하지 않는다.
- 단일 후보만 반환: 사용자의 성능·가성비·확장성 trade-off를 설명할 수 없어 채택하지 않는다.

## 결과

- 후보가 없을 때 임의의 부품을 끼워 넣지 않고 `REVIEW_REQUIRED`와 미충족 조건을 반환한다.
- 성능 결과는 성능 근거를 함께 보유하며, exact 조합이 아닌 결과는 실측으로 표시하지 않는다.
- 견적은 live 가격을 사용하고 주문은 snapshot으로 전환한다.

## 공개 카탈로그 승인 게이트

크롤러가 새 표준 부품을 적재할 때 `IS_ADMIN_APPROVED=N`으로 시작하므로, 운영 API가 production이라는 이유만으로 승인된 부품만 강제 조회하면 활성 판매 데이터가 있어도 카탈로그와 견적이 모두 빈 결과가 될 수 있다. 공개 승인 게이트는 기본적으로 유지하되, 운영자가 `PUBLIC_PART_APPROVAL_REQUIRED=false`를 명시한 환경에서는 `STATUS=ACTIVE`이고 활성 판매 단위·현재 가격·재고를 가진 부품을 공개한다. 설정하지 않거나 `true`인 경우에는 기존처럼 관리자 승인 부품만 공개한다. 부품 목록 API와 견적 미리보기 API는 같은 의미의 게이트를 사용해야 한다.
