# 벤치마크 집계 확장 및 JHS 공개 콘텐츠 정규화

작성일: 2026-09-09
Wayfinder task: #62
Parent map: #54

## 사용자 문제

`/benchmarks`에서 실제 수집 조합이 하나뿐인 것처럼 보이고, `/recommendations`에는 공개 견적이 세 개뿐이다. 조합명이 내부 slug 형태로 표시되어 CPU/GPU 세대를 읽기 어렵고, 외부 수집 문구가 서비스 콘텐츠처럼 보인다.

## 사용자 스토리

- 사용자는 전체 수집 조합 수와 FPS 근거가 있는 조합 수를 한눈에 구분한다.
- 사용자는 FPS가 없는 조합을 보더라도 왜 수치가 없는지 이해한다.
- 사용자는 `Ryzen7 9800X3D + RX 9070XT`처럼 읽을 수 있는 조합명을 모든 관련 탭에서 본다.
- 사용자는 추천 견적을 여러 목적·가격대에서 비교하고, 각 설명이 JHS의 기준으로 작성되었음을 이해한다.
- 운영자는 원천 출처와 내부 키를 잃지 않고 추후 재검증할 수 있다.

## 구현 결정

- `/benchmarks/combos`는 `includeNoFps=true`를 지원 화면의 기본 조회로 사용한다. 각 항목에 `hasFpsEvidence`와 공개 조합명을 제공한다.
- `/benchmarks/summary`의 top combo 집계 필드명을 목록 타입과 맞추고 공개 조합명을 함께 제공한다.
- 프론트 목록과 선택 패널에서는 raw `comboKey`를 고객 문구로 렌더링하지 않는다.
- 추천 목록·상세의 CPU/GPU 표시는 같은 정규화기를 사용한다.
- 추천 생성 Agent는 고정 recipe를 확장하되 실제 부품 선택·가격·재고를 재검증하고, 동일 목적/조합/가격대 게시물을 중복 생성하지 않는다.
- 서로 다른 수집 키가 같은 JHS 공개 CPU/GPU 이름으로 정규화될 때는 목록을 하나로 합치며, 원천 키 전체를 상세 조회 대상으로 유지한다.
- 원본에 해상도별 독립 FPS가 없고 같은 보고값이 반복되면 해상도별 수치로 확장하지 않고 보고값 1건과 근거 주의를 표시한다.
- 고객용 제목·요약·본문은 JHS 템플릿으로 생성하며 원천 증거의 종류를 숨기지 않는다.

## 테스트 결정

- 서버: 집계 필드, FPS 없는 조합, 조합명 정규화, 중복 추천 방지를 단위 테스트한다.
- 프론트: 표시명과 빈 상태를 포함한 타입체크/빌드를 수행한다.
- 운영: 공개 summary/combos/recommendation-posts API와 두 페이지를 smoke test한다.

## 범위 밖

- 새로운 벤치마크를 측정하거나 FPS를 추정해 실측처럼 채우는 것
- 원천 데이터의 provenance 제거
- 추천 콘텐츠를 외부 사이트 문구의 복사본으로 생성하는 것
