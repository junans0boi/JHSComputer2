# FPS 조합 선택형 벤치마크 화면 및 원본 수집 확장

작성일: 2026-09-10  
관련 Wayfinder: #63

## 사용자 문제

현재 `/benchmarks`는 수집 조합 목록을 큰 좌측 패널로 보여주고, 실제 FPS 근거가 있는
조합은 ComputerBase의 단일 테스트 CPU와 제한된 GPU 범위에 머문다. 사용자는 CPU와
GPU를 먼저 고른 뒤 그 조합의 게임 성능과 부품 벤치마크를 바로 비교할 수 있어야 한다.
또한 견적왕·왕가PC의 추천/실제 견적 데이터가 FPS 숫자로 잘못 해석되지 않도록 원본
조건과 근거 수준을 보존해야 한다.

## 결정된 요구사항

1. 견적왕·왕가PC에서 조합별 FPS를 수집한다. 단, 원문에 CPU·GPU·게임·해상도·옵션·
   숫자 FPS가 함께 존재하는 행만 `GameFpsObservation`으로 적재한다.
2. 견적왕의 단일 평균 FPS와 FHD/QHD/UHD “지원 옵션” 문구는 해상도별 FPS가 아니다.
   현재는 추천 맥락으로만 보존하고 FPS 원본으로 적재하지 않는다. 해상도별 행으로
   복제하지 않는다.
3. 왕가PC가 실제 FPS를 제공하지 않는 페이지는 조립 PC 구성·가격 출처로만 적재한다.
   숫자를 추정해 FPS를 만들지 않는다.
4. ComputerBase는 기사별 테스트 시스템과 원문 URL을 저장하고, 차트에 실제로 표시된
   GPU·게임·해상도·옵션·평균 FPS만 적재한다. 기사에 명시된 테스트 CPU가 다른데
   9800X3D로 고정하지 않는다.
5. 모든 외부 수집 요청은 느린 수집 정책(요청 간 지연·지터·배치 휴식)을 사용한다.
   동일한 원본 관측 식별자는 최신 값으로 갱신하고 중복 적재하지 않는다.
6. 화면 상단은 다음 한 줄 선택 영역으로 바꾼다.

   `[CPU 고르기] [GPU 고르기] [제출]`

   선택지는 FPS 근거가 있는 공개 CPU/GPU 모델에서 만들며, 조합이 실제로 존재하지
   않으면 FPS 표에 임의 값을 보여주지 않고 근거 없음 상태를 표시한다.
7. 게임 성능은 한 행을 `게임 + 옵션`으로 묶고 열은 `로고 | 게임명 | 옵션 | FHD | QHD | 4K`로
   표시한다. 각 해상도 셀에는 `평균 FPS (체감 등급)`과 표본/근거를 표시한다. 값이
   없으면 `—`이며 0 FPS로 처리하지 않는다.
8. 같은 조합·게임·해상도·옵션의 여러 출처 값은 서버에서 같은 조건의 관측값만
   집계하고, 원본 URL·출처·표본 수는 상세에서 확인할 수 있게 한다.
9. 선택한 조합의 CPU/GPU 부품 벤치마크를 기존 공용 비교 API로 연결한다. Cinebench
   2024 싱글코어와 멀티코어를 각각 별도 표로 우선 노출하고, 서로 다른 테스트·버전·
   지표를 한 점수로 합치지 않는다.
10. 수집 조합 수, FPS 근거 조합 수, 추천 조합 그룹 수를 서로 다른 지표로 표시한다.

## 사용자 이야기

- 사용자는 CPU와 GPU 드롭다운을 선택하고 제출해 해당 조합의 게임별 FHD/QHD/4K FPS를
  한 표에서 비교할 수 있다.
- 사용자는 게임명·옵션·해상도·FPS·체감 등급을 한눈에 보고, 빈 셀은 데이터 없음임을
  이해할 수 있다.
- 사용자는 선택 조합의 Cinebench 2024 싱글/멀티코어 점수와 비교 대상 부품의 점수 차이를
  별도 표에서 확인할 수 있다.
- 사용자는 FPS 숫자가 ComputerBase, 견적왕, 왕가PC 중 어떤 원본에서 왔는지와 테스트
  조건을 확인할 수 있다.
- 운영자는 수집기를 느리게 실행하고, 같은 관측값이 중복으로 쌓이지 않는 것을 확인할
  수 있다.

## 구현 결정

- 선택 URL은 공개 CPU/GPU 모델을 `cpu`·`gpu` query로 사용하고, 서버는 FPS 근거 조합
  목록에서 정확한 정규화 조합을 찾는다.
- 공개 선택지 전용 API를 추가해 전체 수집 조합을 큰 목록으로 내려보내지 않는다.
- 게임 표의 행 그룹 키는 `benchmarkGame + option + sourceCondition`이며, 해상도 셀은
  기존 `benchmark_combo_game_results`의 해당 관측값만 사용한다.
- 추천 조합 API와 FPS API는 계속 분리한다. 추천 맥락 수를 FPS 표의 표본 수로 쓰지 않는다.
- 수집기 파서는 원본 HTML의 필수 필드가 없으면 레코드를 버리고, 수집 결과를
  `--apply` 전 dry-run으로 검토한다.

## 검증 결정

- ComputerBase parser 단위 테스트: 게임·GPU·해상도·옵션·FPS 추출, 다른 테스트 CPU의
  기사별 보존, 중복 제거.
- 견적왕/왕가PC parser 테스트: 숫자 FPS가 없는 추천/조립 행이 FPS 결과를 만들지 않는지,
  실제 숫자 행이 있으면 해상도별로 정확히 적재되는지.
- API 테스트: CPU/GPU 선택지와 정확한 조합 조회, 존재하지 않는 조합의 빈 결과,
  `FHD/QHD/UHD` 독립 값 보존.
- 프론트엔드 타입체크와 `/benchmarks` 데스크톱·모바일 스모크: 선택 제출, 표 가로 스크롤,
  긴 게임명·출처 URL 줄바꿈, Cinebench 두 표 표시.
- DB 적재 전후 건수 검증: 원본 행 수, FPS 근거 조합 수, 조합-게임-해상도 행 수를 각각
  보고한다.

## 범위 밖

- 데이터가 없는 조합의 FPS 추정·AI 보간·해상도별 복제.
- JHS가 직접 게임을 실행하는 `MEASURED` 계측 장비 구축.
- 외부 사이트의 이용약관·라이선스를 우회한 대량 크롤링.
- Cinebench와 게임 FPS를 합산한 종합 점수.
