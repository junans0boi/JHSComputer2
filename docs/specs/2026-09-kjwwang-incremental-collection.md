# 견적왕 느린 증분 추천 조합 수집

작성일: 2026-09-10
Wayfinder map: #63
상태: 구현 승인

## 사용자 문제

견적왕 게임 상세에는 게임·해상도·등급별 추천 CPU/GPU 조합이 있지만 현재 수집기는
요청 간 지연과 재개 지점이 충분하지 않아 전체를 안정적으로 누적하기 어렵다. 같은
추천 맥락을 다시 가져오면 중복 데이터가 늘고, 최신 추천으로 바뀌었을 때 무엇을
공개해야 하는지도 불분명하다.

## 사용자 스토리

1. 운영자는 수집기를 실행해도 견적왕에 급격한 요청을 보내지 않는다.
2. 운영자는 중간에 프로세스가 멈춰도 다음 실행에서 마지막 미완료 페이지부터 재개한다.
3. 운영자는 같은 출처·게임·해상도·등급·플랫폼·CPU/GPU 맥락을 다시 수집하면 최신값으로 갱신된 것을 확인한다.
4. 사용자는 CPU/GPU 조합을 한 번만 보고, 필요하면 게임·해상도별 추천 맥락과 최신 확인 시각을 본다.
5. 사용자는 견적왕의 목표 FPS 문구와 실제 FPS 측정값이 섞이지 않은 것을 확인한다.

## 결정된 요구사항

### 수집 속도와 재개

- 기본 요청 간격은 6초 이상이다.
- 요청 간격에는 작은 무작위 지연을 추가한다.
- 일정 페이지마다 긴 휴식을 넣는다.
- 429·5xx·네트워크 오류는 `Retry-After`와 지수 백오프를 적용한다.
- 진행 파일에는 대상 목록, 완료/실패 상태, 마지막 HTTP 조건부 요청 헤더, 캡처 시각을 기록한다.
- 기본 실행은 소량 페이지를 처리하며 `--limit`으로 배치 크기를 명시할 수 있다.

### 중복과 최신값

`RecommendationContextKey`는 다음을 포함한다.

```text
source + game + resolution + tier + platform + normalizedCpu + normalizedGpu
```

동일 키는 하나의 최신 추천 스냅샷으로 갱신한다. 동일 CPU/GPU라도 게임·해상도·등급이
다르면 추천 맥락이므로 보존한다. 공개 조합 목록은 `PublicComboKey`(정규화 CPU + GPU)
로 묶고, `buildSampleCount`를 중복 조합 개수처럼 오해하게 표시하지 않는다.

### FPS 표현 경계

견적왕의 평균 목표 FPS, 지원 옵션, 권장 사양은 추천 메타데이터로만 저장한다. 실제
FPS 숫자·게임 버전·해상도·품질·테스트 시스템·드라이버가 모두 확인된 원문이 없는
한 `GameFpsObservation`을 생성하지 않는다.

## 구현 결정

- 기존 `benchmark_builds`는 추천 맥락 스냅샷의 저장 경계로 사용한다.
- 동일 출처 외부 식별자는 upsert하고 `RAW_JSON`과 `UPDATED_DT`를 최신값으로 갱신한다.
- 파서 결과는 DB 반영 전에 `RecommendationContextKey`로 dedupe한다.
- 진행 상태 파일은 수집 샘플 디렉터리에 저장하고 Git에 커밋하지 않는다.
- 수집기는 dry-run과 apply를 분리한다.

## 테스트 결정

- 요청 계획이 기본 지연·jitter·휴식·재시도 정책을 지키는지 테스트한다.
- 같은 추천 맥락은 한 건으로 dedupe하고 다른 게임/해상도/등급은 분리하는지 테스트한다.
- 재개 시 완료 페이지를 건너뛰고 실패 페이지를 재시도하는지 테스트한다.
- 429 응답의 `Retry-After`를 존중하는지 테스트한다.
- 목표 FPS 문구를 FPS 측정값으로 생성하지 않는 기존 계약을 유지한다.
- 실제 적용 전 소량 dry-run → dev DB apply → API smoke 순서를 지킨다.

## 완료 기준

- 견적왕 전체 대상 목록을 소량 배치로 나누어 중단 후 재개할 수 있다.
- 같은 추천 맥락은 최신 스냅샷 하나로 유지된다.
- 공개 조합은 CPU/GPU 기준으로 중복 표시되지 않고 추천 맥락 수는 별도 의미로 표시된다.
- 수집 요청 간격과 오류 백오프가 로그에 남는다.
- 견적왕 추천 문구가 FPS 실측값으로 노출되지 않는다.

## 범위 밖

- 견적왕에서 확인되지 않은 실제 FPS 생성
- ComputerBase의 모든 카탈로그 부품 조합 자동 생성
- 운영 DB 초기화
